01 · 배경

이 리소스는 무엇을 하나

클라우드 네트워크 용어가 몇 개 나온다. 먼저 짧게 풀어 둔다.

말쉽게 말하면
인스턴스빌려 쓰는 서버 한 대
트래픽오가는 데이터
공인 IP인터넷 어디서나 닿는 주소. 밖에서 이 주소로 들어올 수도 있다
사설 IP내 네트워크 안에서만 통하는 주소. 밖에서는 닿지 못한다
사설 서브넷사설 IP만 쓰는 구역
플로팅 IP따로 발급받아 원하는 리소스에 붙였다 뗐다 하는 공인 IP
인터넷 게이트웨이구역 하나를 인터넷과 이어 주는 출입구
라우팅 테이블어떤 주소로 가는 트래픽을 어디로 보낼지 적어 둔 표
네트워크 인터페이스리소스가 네트워크에 꽂는 랜카드에 해당하는 것

사설 서브넷의 인스턴스는 공인 IP가 없다. 그래서 밖으로 못 나간다.

인스턴스마다 공인 IP를 붙이면 들어오는 길까지 열린다. 나가는 것만 열고 싶을 때 쓰는 것이 NAT 게이트웨이다.

무엇을어떻게
공인 IP 확보게이트웨이 하나에 플로팅 IP를 붙인다
트래픽 유도라우팅 테이블에 그 게이트웨이로 가는 경로를 넣는다
결과인스턴스는 공인 IP 없이 밖으로 나간다

혼자 쓰이는 화면이 아니다. 앞뒤로 다른 리소스가 물려 있다. 화면 제약 대부분이 그 관계에서 나온다.

02 · 핵심

앞뒤 관계 하나가 화면을 결정한다

NAT 게이트웨이는 아래 그림 한가운데 있다. 위는 만들기 전에 먼저 있어야 하는 것이고, 아래는 만들고 나서 이것을 쓰는 것이다.

VPC
네트워크의 가장 바깥 단위
안에
서브넷 + 인터넷 게이트웨이 연결
외부로 나가는 길이 이미 뚫려 있어야 한다
여기에
NAT 게이트웨이 + 플로팅 IP
공인 IP를 하나 달고 대신 나가주는 창구
경로로 지정
라우팅 테이블
어떤 트래픽을 이 게이트웨이로 보낼지 정한다

이 관계만 알면 화면의 제약이 전부 설명된다.

화면에서 보이는 제약왜 그런가
생성 모달이 VPC → 서브넷 순서다 서브넷은 VPC 안에 있다. 위를 골라야 아래가 좁혀진다
인터넷 게이트웨이가 붙은 서브넷만 고를 수 있다 밖으로 나가는 길이 없는 서브넷에 두면 아무 일도 못 한다
플로팅 IP가 반드시 필요하다 공인 IP가 있어야 대신 나가줄 수 있다
라우팅 테이블이 쓰는 중이면 삭제가 막힌다 경로가 가리키는 대상이 사라지면 트래픽이 갈 곳을 잃는다
반대 방향으로도 걸린다. 이 게이트웨이에 붙은 플로팅 IP는 연결을 해제할 수 없고 삭제 보호 설정도 못 한다. 게이트웨이가 만들어낸 네트워크 인터페이스도 따로 손댈 수 없다. 이 화면을 고치면 플로팅 IP 화면과 네트워크 인터페이스 화면에도 영향이 간다.
03 · 사용자 흐름

사용자는 이 화면을 어떻게 지나가나

목표별로 여섯 갈래다. 도표는 화면 정의서의 FLOW 절에 있다. 여기서는 어디서 막히는지만 짚는다. 흐름마다 여러 개다.

UF-01 목록 확인

  • 상태 코드가 목록에 문자열로 없다. 아이콘에 마우스를 올려야 확인된다
  • 이름으로 못 찾으면 검색 항목을 ID로 바꿔 다시 찾아야 한다. 고를 수 있는 항목이 그 둘뿐이다
  • 페이지 나눔이 없다. 항목이 많으면 한 화면에 전부 그리고, 찾는 것은 스크롤로만 한다
  • 설명 칸은 정렬이 되지 않는다

UF-02 생성

  • 고를 수 있는 서브넷이 없으면 여기서 끝난다. 인터넷 게이트웨이를 먼저 연결해야 하는데 그건 다른 화면 일이다
  • 인터넷 게이트웨이가 없는 서브넷은 목록에 보이되 고를 수 없다. 왜 못 고르는지 알려 주지 않는다
  • VPC · 서브넷 · 플로팅 IP를 고르지 않고 확인을 누르면 빨간 테두리만 나오고 문구가 없다. 무엇이 잘못됐는지 스스로 짚어야 한다
  • 이미 다른 리소스에 연결된 플로팅 IP도 목록에 남아 있다. 눌러도 골라지지 않는다

UF-03 플로팅 IP 확보

  • 발급받아도 자동으로 선택되지 않는다. 드롭다운을 다시 열어 골라야 한다
  • IP 풀이 둘 이상이면 행이 한 번 더 펼쳐진다. 생성 버튼을 두 번 누르는 셈이다

UF-04 수정

  • 2건 이상 고르면 진입 자체가 막힌다
  • 들어가도 고칠 수 있는 것은 이름과 설명뿐이다. 나머지가 왜 잠겼는지 화면에 설명이 없다

UF-05 삭제

  • 라우팅 테이블이 쓰고 있으면 막힌다. 어느 테이블인지는 연결 정보 탭에서 본다
  • 여러 개를 골랐을 때 하나만 걸려도 버튼 전체가 잠긴다. 어느 것이 걸렸는지는 하나씩 골라 봐야 안다

UF-06 상세 확인

  • 막히는 지점 없음
UF-02와 UF-05가 서로 거울이다. 만들 때는 인터넷 게이트웨이가 먼저 있어야 하고, 지울 때는 라우팅 테이블이 먼저 비어 있어야 한다. 위에 있는 것과 아래에 있는 것을 각각 확인하는 셈이다.
04 · 만드는 동안

만들어지는 동안 화면이 하는 일

생성 요청을 보내면 곧바로 쓸 수 있는 것이 아니라 준비 단계를 거친다. 그래서 목록은 진행 중인 항목이 있을 때만 스스로 다시 조회한다.

상태뜻표시자동 재조회
BUILD준비 중회전 표시함
ACTIVE사용 가능초록 점안 함
ERROR실패빨간 점안 함

상태는 이 셋이 전부다.

목록 칸에는 글자가 없다. 점 아이콘 하나뿐이다. 대체 텍스트도 없다. 색을 보거나 마우스를 올려야 코드를 알 수 있다. 문자열은 하단 상세에만 나온다.

05 · 조작 규칙

버튼이 잠기는 세 가지 이유

버튼 하나가 잠겨 있을 때 원인이 셋 중 하나다. 툴팁을 보면 어느 쪽인지 구분된다.

① 선택 개수

선택생성변경삭제
0건활성비활성비활성
1건활성활성활성
2건 이상활성비활성활성

변경은 고칠 대상을 하나로 특정해야 해서 단건 전용이다. 이때 툴팁은 NAT 게이트웨이를 하나만 선택하세요.

② 다른 리소스가 쓰는 중

1건만 골랐는데도 삭제가 잠기는 경우가 있다. 선택한 항목에 삭제 차단 사유가 붙어 있을 때다. 현재 사유는 하나뿐이다.

사유 코드툴팁
RELATED_NAT_GATEWAY_TO_ROUTING_TABLE 라우팅 테이블에서 사용 중인 NAT 게이트웨이는 삭제할 수 없습니다.

어느 라우팅 테이블이 쓰는지는 하단 상세의 '연결 정보' 탭에서 확인한다.

③ 권한

생성·변경·삭제는 NAT_GATEWAY_ADMIN 권한이 필요하다. 상위 관리자 역할로도 통과한다.

권한이 없으면 선택 건수와 무관하게 잠긴다. 툴팁도 권한이 없습니다.로 덮인다.

대상권한 검사
생성 · 변경 · 삭제 버튼, 우클릭 메뉴함
새로 고침 버튼안 함 — 유일하게 빠져 있다
변경으로 고칠 수 있는 것은 이름과 설명뿐이다. VPC · 서브넷 · 플로팅 IP는 모달에서 모두 잠겨 있다. 어디에 붙어 있는지를 바꾸는 일이라 만든 뒤에는 못 바꾼다. 그래서 이 기능은 '변경'보다 '수정'이 맞고, 개편 시 그렇게 바꾼다.
06 · 리뷰 초점

이 정의서는 무엇으로 만들었나

기획서가 남아 있지 않아 지금 동작하는 화면과 코드가 유일한 근거다. 항목마다 근거가 다르고, 근거에 따라 틀렸을 위험도 다르다.

근거해당 항목리뷰에서 볼 것
코드 권한 규칙 · 상태 코드 3종 · 이름 32자와 허용 문자 · 설명 255자 · 변경 단건 조건 · 삭제 차단 사유 · 기본 정렬 비교적 안전하다. 코드가 바뀌면 같이 바뀌는지만 본다
화면 플로팅 IP 자동 선택 안 됨 · 사용 중 IP 비활성 · 다국어 표기 일반화가 맞는지 본다. 특정 조건에서만 그럴 수 있다
확인 필요 설명 컬럼 정렬 여부 여기부터 본다. 아래 설명 참조

확인이 필요한 항목 하나

내용무엇이 걸리나
설명 컬럼만 정렬 설정이 다르다 정렬 기준은 지정돼 있고 표시만 빠졌다. 의도인지 누락인지 코드로는 모른다
리뷰에서 가장 도움이 되는 지적은 '여기 빠졌다'이다. 적힌 내용이 틀린 것보다, 화면에도 코드에도 드러나지 않아 아예 적히지 못한 규칙이 더 위험하다. 예를 들어 조건이 맞지 않아 이번에 노출되지 않은 항목이 둘 있다.
